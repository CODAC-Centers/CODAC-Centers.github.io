Sheaf Explorer

Cellular Sheaf Explorer

The explorer computes global sections of a cellular sheaf over a graph and renders them in the browser. It is the same engine as the multi-domain tracking demo, with everything the demo leaves out: the other examples, an editor for writing a sheaf of your own, and the analytics panels that justify the readouts.

Open the explorerOpens in a new tab. Runs entirely in your browser — nothing is sent anywhere.

It opens in a tab of its own rather than in a frame on this page. The explorer puts the source editor, the example picker and the analytics panels beside the formation, and at the width a page of prose can offer, every one of them is too narrow to use.

The examples

The picker in the top right carries six sheaves, each built to isolate one thing. They run simplest first, and each is a single step from the one before it; the explorer opens on the braced square.

ExampleWhat it shows
Braced squareThe rigidity sheaf on a square with one diagonal. Each edge constrains the component of relative motion along its own length, which is exactly the framework’s rigidity matrix. The brace removes the shear, leaving the Euclidean trivial motions.
Bare squareThe same square with the brace deleted and nothing else changed. The readout goes from 3 to 4, and sweeping the extra null vector animates the square shearing into a rhombus.
Degenerate triangleThree collinear agents, every pair joined. The framework is rigid — no other configuration has those three distances — but the sheaf does not see it, because the sheaf linearises. This is where that costs you something.
Offset formationA formation held by offset rather than by distance. Every edge constrains $p_{\text{to}} - p_{\text{from}} = \delta$ exactly, instead of constraining only its component along one frozen direction.
Infeasible cycleA doubly-braced square with an offset on one edge, and no global section at all. An offset can only break feasibility where the framework carries a self-stress, and the second diagonal is what creates one.
Multi-domain trackingShips in $\mathbb{R}^2$ and targets in $\mathbb{R}^3$, linked by the projection that forgets altitude. Which agents can track which is a question about $H^0$.

The source panel

Sheaves are plain TOML — vertices with stalk dimensions, edges with restriction maps — and the editor reparses as you type. Errors are reported with the line and column they occur at, and clicking one selects the offending span in the text, so a malformed sheaf points at itself rather than at a stack trace.

Editing is local to the tab. Nothing you write is uploaded or saved anywhere, and reloading restores the example as shipped.

The analytics panels

The demo page describes the controls, which are the same here. What the explorer adds is the evidence behind them:

  • Spectrum of $L_{ff}$ plots the eigenvalues on a log axis with the rank threshold drawn across them. With real-valued restriction maps a rank needs a threshold, and an integer that depends on one is worth being able to check — the plot makes the gap visible, and gives $\lambda_2$, the convergence rate, as a number. Eigenvalues at or below the threshold are drawn hollow rather than only recoloured, so “in the nullspace” is never carried by colour alone.
  • Dirichlet energy is $\tfrac{1}{2}\lVert Dp - c \rVert^2$ for the current configuration: what the diffusion flow descends, and what a true rotation visibly fails to keep at zero.
  • DOF remaining is $\dim \ker L_{ff}$, the freedom the pins leave.

Relationship to CellularSheaves.jl

The explorer implements the same construction as CellularSheaves.jl in the AlgebraicJulia ecosystem, in the browser and with no server. The names follow that library’s, camel-cased, so a reader who knows one can read the other.
